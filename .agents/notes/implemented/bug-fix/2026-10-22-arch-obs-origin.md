# Agent Note: Arch 软件源避开失步的 OBS 下载镜像

Status: implemented

## Problem

msime#9173 的“签名无效”可以在官网下载指引使用的 OBS 入口复现：数据库及其签名是新版本，下载路由选中的镜像仍返回同版本名的旧包。重新信任公钥不会改变包的字节。

2026-10-22 核对 `msime-bin-0.12.1-1-x86_64.pkg.tar.zst`：数据库声明 63052074 字节、SHA-256 `209a9e316b31a33e597ec5249fc8259b9e2c2c0fa9a64ad5510b0871889b9a70`；下载入口重定向到的旧镜像给出 63051760 字节、摘要 `01bdf275545ee98b7953c46ee198ff0f8215902b7404a263ae089a3face1d28f`。数据库内的签名和独立 `.sig` 一致，公钥指纹也与官网相同。OBS 源站的包与数据库匹配，同一签名验证通过。

## Decision

Arch 的官网命令和安装脚本使用 `downloadcontent.opensuse.org` 源站，避免数据库与包从同步代次不同的镜像下载。其他发行版保持原下载入口。安装脚本重跑时仅迁移 `[home_msime_Arch]` 节中由旧脚本生成的默认 `Server`，保留其他仓库和用户自定义镜像。现有安装用户的手动修复说明与之保持一致，并说明按 pacman 提示删除对应无效包后重试，保留签名校验。

## Existing notes

检索本仓现有五篇笔记，没有拥有 OBS 地址和 pacman 配置迁移决定的记录；下载统计笔记只说明软件源不计入下载次数，与本次修复无关。

## Alternatives considered

- 重新导入公钥适用于本机缺失公钥或没有信任的情况；这里数据库签名已能验证，源站包也能验证，无法修正旧包字节。
- 保留镜像分流可以减少源站带宽并利用就近节点；本次路由实际返回过旧包，pacman 只能报验签失败，不能在验签后自动选另一个镜像，因此 Arch 先固定源站。
- 停止签名校验可以绕过报错，但会接受数据库不匹配的旧包并失去来源验证，不采用。

## Verification

安装夹具真实执行 `public/install.sh`，只把固定系统路径换到临时目录，并用合成包管理器和网络命令接住外部动作。旧版的新源地址和迁移两项失败，修改后新安装、受限迁移、备份保存、自定义镜像和幂等三项通过；配置仍要求签名，安装仍使用完整系统升级 `-Syu`。

源站实际包的 SHA-256、长度和 GPG 签名与已验签数据库一致，下载入口选中的旧镜像包则与数据库不符、同一签名验证失败。这是下载字节的对照验证；没有在报告人的 Arch 系统里实际安装。

## Consequences

Arch 从源站取数据库、包和公钥，规避已复现的镜像代次不一致；旧默认地址由安装脚本迁移，修改前保留 `.msime-backup`，重复运行不覆盖该备份。自定义镜像与其他仓库不由本脚本接管。

源站访问速度可能低于就近镜像；不可达时仍由 curl 或 pacman 报错，不退回已知失步镜像、不关闭校验。本改动不重新发布或重签 OBS 包。
