# Agent Note: 累计下载包含国内镜像

Status: implemented

本文的浏览器镜像采集、当前附件重算及 iOS 不进入总量的决定，相关部分由[补齐下载累计的可采集缺口](../feature/2026-10-22-complete-download-counts.md)替代；原始决定与验证记录保留。

## Problem

官网已上报国内镜像点击，却把它排除在「累计下载」之外。维护者要求统计总下载，不允许按来源排除镜像。[原安装包统计决定](../feature/2026-10-21-installer-download-statistics.md)的渠道排除口径因此被本决定替代。

## Decision

累计下载等于现有 GitHub 安装包快照与全部历史国内镜像计数之和，各平台按同一公式合计。页面统一显示累计下载，不再提供按来源划分的数字。镜像来自后端公开只读 `/v1/site/download-stats`，不使用需要管理员权限且只覆盖最近一周的后台汇总。

Pages Function 每分钟刷新镜像计数，失败保留最近成功缓存。清单生成器也保存 `mirrorDownloadStats`，用于简繁预渲染和运行时回退。静态和实时镜像数据只选较新的一份，再与 GitHub 相加，不把两份镜像重复计算。首次缺少镜像数据时标为统计暂不可用，不能把部分数标为总数，也不能凭空补零。未知平台镜像仍计入累计数，列入其他下载。iOS 的 TestFlight 安装量继续独立展示。

主仓库 Windows 包的镜像事件按真实 GitHub URL 标记 `windows-rust`，与纯净版区分。历史 Windows 事件缺少产品仓库信息，不能还原当时 Rust 与纯净版的准确镜像分项，现有 Windows 计数原样保留，不丢总数。

半小时清单同步仍经自动 PR 和既有门禁，镜像首次失败不发布伪造总数，后续失败保留已有镜像快照。顶层及镜像获取时间变化不触发空 PR。新接口部署后才生成首份真实镜像快照，不在源码填写估计值。

## Alternatives considered

只改文案可以最快展示「总下载」，但数值仍漏镜像，无法满足统计目标。让后端重新抓取 GitHub 并生成全部总数可以集中来源，但其快照刷新频率与官网不同，也会复制安装包分类逻辑，因此复用官网现有完整分页快照，仅补缺失的镜像累计值。

## Consequences

镜像历史计数进入公开累计值，静态和动态页面口径一致，失联不清零。代价是增加一次只读公开请求，后端必须先提供接口。镜像仍按已有官网点击计数，不代表完成下载；软件源和蒲公英没有可用计数，未上报的历史无法补回。

接口与缓存用例验证合计守恒、未知平台、真实零、无数据、故障保留、较旧响应不覆盖新快照和 Windows 产品识别；SSR 用例验证简繁页面跨来源相加、TestFlight 不进入累计以及不可用状态。

上线核验发现 Pages Function 文件存在并不代表公网会执行：`public/_routes.json` 的显式白名单必须同时包含 `/api/download-stats` 与尾斜杠路径，否则只会回退快照并得到 404。补齐白名单，并将部署路由断言加入镜像接口测试；验收同时读取线上简繁页面与 JSON 接口。
