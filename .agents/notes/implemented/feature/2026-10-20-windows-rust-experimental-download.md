# Agent Note: Windows Rust 新版测试版独立下载入口

Status: implemented

## Problem

官网 Windows 下载入口来自 `MSIME-Windows`，主仓库 `msime` 发布的 Rust 重写版安装包无法从下载页找到。两条产品线的版本号不具有可比较性，Rust 版仍不稳定，不能直接替代正式版。

## Decision

清单在 `platforms.windows.experimental` 独立保存主仓库版本最高、包含可识别安装包的 Windows 发布，正式发布和预发布均可进入此槽位。完整版排在前面，其他版本沿用统一的版本名称。下载页复用预览版展示组件，标注「新版测试版」和不建议主力使用的提醒。

测试版的签名状态为 `null`：旧仓库根据文件名判断签名的约定不适用于主仓库安装包。测试版不配置国内镜像；旧正式版下载和客户端 `update.json` 继续使用原来源。旧清单没有 `experimental` 或该字段损坏时，只隐藏测试版入口。

清单生成器按仓库去重读取完整发布列表，测试版选择与[安装包下载统计](2026-10-21-installer-download-statistics.md)共用同一份主仓库数据，保留统计字段与总数校验。检索现有笔记后，统计笔记与本项仅部分重叠，候选窗皮肤下载的两篇笔记无关，均原地保留。

## Alternatives considered

把新包接入正式版选择器可复用主按钮，但两个独立版本序列会混淆正式版来源，且会将不稳定安装包默认推荐给所有访客，因此保留独立入口。

## Consequences

用户可从官网下载新 Windows 产品，同时继续取得原正式版。增加一个可选清单字段和测试版显示入口，主仓库改包名时需要同步识别规则。现存快照没有该字段时，入口需等待下一轮下载清单同步后显示。

生成器测试覆盖最高版本、草稿及空产物过滤、版本排序、未知签名和与旧正式版安装包隔离；数据适配测试核对损坏或缺少测试版数据不会丢失正式版及下载统计。

## Verification

`pnpm test` 的 264 项用例、`pnpm lint`、8 项 Python 自动化限制测试、笔记的三条校验及 `git diff --check` 均通过。本机磁盘不足 50 GB，完整构建在远端执行，包含 TypeScript 检查和 23 项静态页面测试。远端子模块路径按实际镜像目录修正后，构建通过。

实时运行生成器选中 `v0.3.0-beta` 的 6 个安装包，且生成下载统计。将此测试版块临时注入现有快照后构建，用独立 Chrome 上下文检查简繁页面在 1280px、390px 下的测试版主按钮、全部安装包、原 Windows 正式版链接、五项下载统计、无横向溢出及无页面异常；接口使用合成失败响应，没有真实账号或下载事件写入。临时快照不提交，正式入口随既有下载同步流程发布。
