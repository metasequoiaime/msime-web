# Agent Note: 官网公开展示安装包下载统计

Status: implemented

本文的浏览器镜像采集、当前附件重算及 iOS 不进入总量的决定，相关部分由[补齐下载累计的可采集缺口](2026-10-22-complete-download-counts.md)替代；原始决定与验证记录保留。

本文「国内镜像不计入」的口径由[累计下载包含国内镜像](../bug-fix/2026-10-22-total-downloads-include-mirrors.md)取代；GitHub 资产分类、分页去重和清单发布机制继续适用。

## Problem

官网有各平台的下载入口，但访客无法了解已有下载量。后台同时保存 GitHub 资产快照和国内镜像点击，上报点击与文件下载不是同一口径，直接相加或者把次数称为安装人数会误导读者。

## Decision

下载页在下载入口之后展示「下载与安装统计」，含累计次数和 Windows 纯净版、Windows Rust 新版、macOS、Linux、Android、HarmonyOS 六项，并展示 iOS 的数据状态。统计由现有清单生成器完整分页读取 `MSIME-Windows`、`msime` 和归档的 `MSIME-Linux`，在同一份 `platforms.json` 中发布；主仓库的多平台包共用一次读取。保留现有半小时同步、自动 PR、CI 与 Pages 发布集成，不新增公开后端权限或浏览器遥测。

统计按仓库与 GitHub 资产 ID 去重，覆盖正式版、预发布、nightly 及各产品版本的手动安装包，排除源码、词库、校验文件、符号和自动更新载荷。无效的计数或任一分页失败使本轮同步失败，不发布部分总数。累计次数严格等于六个数值分项之和。Windows 纯净版来自 `MSIME-Windows`，Rust 新版来自 `msime`；早期 Rust 产物与旧版同名，因此按来源仓库拆分，不能只靠安装包名称区分，也不把 Rust 数值再加进旧 Windows 合计。

页面明确说明：下载次数不等于安装人数；国内镜像、软件源、蒲公英和 TestFlight 不计入；删除或替换资产的历史计数无法补回。显示时间沿用快照的 `generatedAt`，简繁界面与静态预渲染使用相同数据。旧快照缺字段或者统计校验失败时只隐藏统计区，不影响安装包入口。旧统计没有 `windowsRust` 时保留合并后的 Windows 数值并注明含 Rust 新版，Rust 项显示「尚未单独统计」。旧统计缺少 HarmonyOS 分项时也显示该状态，不补零。

## Alternatives considered

从管理后台聚合现有 GitHub 与镜像数据能扩大渠道覆盖面，且可展示近期变化。但后台接口需要管理员权限，现有公开接口只提供社区内容统计；官网不持有后台权限，也不把按钮点击混作已完成下载。本次保留独立统计口径；如需跨渠道统计，应先由后端提供经过明确口径定义的公开接口。

新增 Pages Function 实时遍历 GitHub 可以缩短更新延迟，并减少快照发布次数。但下载清单同步已经读取全部发行版，为每个边缘缓存重复遍历会增加延迟与 GitHub 请求量。统计不要求实时，故复用已有同步与静态数据，避免增加运行时请求链路。

## Consequences

访客能在简体和繁体下载页及无 JavaScript 的静态正文中看到可核对的次数，不产生新的访客追踪。代价是下载量变化也会触发既有下载清单自动 PR；数据要等同步和 PR 发布，且现存资产删除后总数可能下降，不能声称产品全部历史下载。

资产文件名是统计分类的边界。新增打包格式或产品命名时需同时更新 `scripts/download-stats.mjs` 和对应测试。统计区同时保留没有可用计数的平台：iOS 由[独立的 TestFlight 安装统计](2026-10-21-testflight-install-statistics.md)接收 Apple 构建指标，首次成功同步前显示「暂无公开数据」；HarmonyOS 统计 GitHub 上的 HAP 测试安装包，包括 nightly 与 unsigned 包，并在计数旁明确测试包口径。未知计数不写成 0，也不参与总数；iOS 的 TestFlight 安装量不由 GitHub IPA 或模拟器产物下载推算。

## Verification

生成器测试覆盖各平台与产品版本、预发布、nightly、归档仓库、分页重叠去重、完整翻页、途中失败、无效计数及排除非安装包。数据适配测试覆盖缺字段、错误总数和坏统计不影响下载入口，以及旧 Windows 合并统计的兼容。生成器额外验证同名安装包按仓库分开、总数守恒；静态 HTML 测试核对两种语言的数字、更新时间、全部分类与未知计数的状态。

`pnpm test` 的 266 项用例、`pnpm lint`、`pnpm exec tsc --noEmit`、Python 自动化限制的 8 项用例、笔记的三条校验和 `git diff --check` 均通过。本地复用现有依赖进行测试和类型检查；本机与远端工作盘都不足 50 GB，因此不创建新的构建树，锁文件安装后的完整构建与 23 项静态页面检查由 PR CI 执行。

快照更新只替换 `downloadStats` 与生成时间，保留原下载入口和已经验证过的镜像地址；鸿蒙 nightly HAP 的实际计数包含在内。简繁页面和桌面、手机布局通过 Pages 预览检查，测试不发送真实下载事件。
