# Agent Note: 补齐下载累计的可采集缺口

Status: implemented

## Problem

已上线的累计下载仍漏掉直接访问镜像的安装包请求，浏览器上报失败也无法重试；附件删除会让仅靠当前发行列表重算的历史下降。iOS 已取得 Apple 安装次数，但被排除在用户要求的全平台累计之外。

## Decision

累计纳入已有 iOS 安装次数，并继续标注它是 Apple 安装指标。沿用统一总数和平台分项，不展示来源数字。

镜像 Worker 对成功发出文件的 GET 起始响应记录一次下载，HEAD、失败响应、后续 Range 和自动预热不记。安装包判定复用官网分类。事件先写入现有 R2 的私有发件箱，每分钟最多读取 100 条，用同一事件 ID 向既有匿名遥测接口投递，成功后才删除；重试与并发定时任务不重复累计，不保存访问者资料。网站停止对本站镜像发出另一份点击事件，蓝奏和夸克维持现有点击口径。浏览器缓存里的旧页面可能在迁移窗口仍报告点击，这一历史不能靠猜测扣除。

发行清单保存按仓库和附件 ID 去重的已知最高累计记录，后续附件删除或替换不抹掉已记录历史；同一 ID 的新计数覆盖旧计数而非叠加。首次接入前已删除、未保存的附件不补估算。

蒲公英使用已配置的 `PGYER_API_KEY` 从官方短链接解析并定位 Android 应用，再完整分页读取 `/apiv2/app/builds`。实际响应含文档尚未列出的 `buildDownloadCount`：首次读取的 9 个版本合计 4,085 次。按版本标识的 SHA-256 摘要保存最高累计到现有清单，删除版本仍保留已读取值；计数加入 Android 分项和统一总数。今日计数不参与累计，凭据与原始应用详情不公开。接口错误、缺字段或分页异常时保留最近成功快照，首次没有有效快照则同步失败；未配置凭据时不伪造零。软件源仍缺数据。

## Alternatives considered

只增加浏览器点击重试最容易落地，也能减轻瞬时网络丢报，但仍读不到绕过官网的镜像下载，并把失败导航记作下载。改为下载侧记录、持久发件箱重试可补这个缺口。Cloudflare Queues 能提供自动重试和批量消费，但会新增资源、配置和消息过期窗口；已有 R2 可以保存小型匿名事件，直到成功投递，不新增存储服务。仅保存平台总量的最高值能防止数字下降，但某附件删除被另一附件增长掩盖时仍丢历史，采用按附件保留。

## Consequences

已取得的 iOS 次数加入总量，附件已知历史不会因删除而丢弃，镜像直接请求和上报重试可被记录。代价是每次安装包起始响应多一次小型 R2 写入，以及每分钟有界的后台投递；R2 写入失败只记错误码而不阻断下载。发件箱不是公开下载路径。

镜像记录发出响应而非完整接收文件，外部网盘仍只有官网点击；自动预热回源会增加上游下载数，现有历史无法精确扣除。原浏览器缓存中的旧页面可能在迁移窗口仍报告点击，这一历史不能靠猜测扣除。安装与文件次数混合后不代表人数。首次读取之前已删除的蒲公英版本仍无法补回，字段未写入官方文档也带来兼容风险，校验拒绝缺失计数；无法宣称完整精确。

单测覆盖起始响应、HEAD、续传、预热、失败响应、发件箱保留与稳定 ID 重试，以及附件删除、替换和重复同步；蒲公英覆盖完整分页、版本去重、历史保留、真实零、无效计数和错误响应不回显。SSR 检查简繁页面总数等于全部平台分项，包括 iOS 的真实零与未知状态。线上验收仅使用 HEAD 和公开统计读取，不制造下载事件。
